The graph is authored in the canonical USD at `/jackal/ActionGraph` in `scenes/CAMERASYNCSSMOETIMES.usd`. It is not duplicated in `isaac/action_graphs/`. The saved scene inspection found a `/cmd_vel` ROS 2 Twist subscriber, ROS context and playback tick, linear unit conversion, vector breaks, a differential controller, and articulation controller outputs to four wheel joints.

Observed robot prim: `/jackal`. Wheel joint token list: `front_left_wheel_joint`, `front_right_wheel_joint`, `rear_left_wheel_joint`, `rear_right_wheel_joint`. Differential geometry: wheel radius 0.098 m, wheel distance 0.3755 m. Controller node exposed limits (in stage-scaled units): max acceleration 29.0000004, angular acceleration 55.0000008, angular speed 29.6000004, deceleration 87.3000013, linear speed 97.7000015, wheel speed 202.5000030. The high numeric limits and unit conversion must be verified in Isaac Sim before treating these as SI; `config/simulation.yaml` records only confirmed geometric values.

A stage-level camera graph uses one 640×400 render product and publishes depth on `/oak_d/depth` with camera info on `/oak_d/camera_info`, and RGB on `/oak_d/rgb/image_raw` with camera info on `/oak_d/rgb/camera_info`. All use frame `oak_d_optical_frame`. A legacy `ROS2CameraHelper` on `/oak_d/camera_info` remains disabled. The camera is `/jackal/base_link/DM9098Pro_enclosure/OAK_D_Pro_RGB`, at the enclosure origin, facing along its forward axis. Its clipping range is 0.05–1000 m. The previously saved camera translation was billions of meters from the rover. The corrected pose and new RGB pipeline need visual and ROS runtime acceptance in Isaac Sim; calibration and the precise mount placement are not yet verified against physical hardware.

The archived camera setup scripts reference an obsolete `/World` camera and must not be run against the canonical stage. The USD owns the graph; the startup launcher does not run those scripts. The graph only ticks during playback.
